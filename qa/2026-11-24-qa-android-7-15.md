# QA: Safestart kiosk på Android 7–15 (API 24–35)

Dato: 2026-11-24
App: `no.safestart.kiosk` (Safestart UB), bygget med `app/build.sh`
Testet av: QA-oppsett i `qa/harness/` (emulator + adb, Device Owner, skripting)
Forgjenger: `qa/2026-11-23-qa-utflukter.md` (kun API 23, kodelesing) og
`qa/2026-11-23-api-compat-audit.md` (statisk kompatibilitetsanalyse)

---

## 1. Kort oppsummert

Appen ble opprinnelig testet bare på Android 6 (API 23). Denne runden kjører
appen på hver hovedversjon av Android fra 7 til 15, ett API-nivå om gangen, på
en headless arm64-emulator, og sammenligner **to bygg**:

| Bygg | Fil | SHA-256 |
|---|---|---|
| `v0` – uendret app | `qa/artifacts/Safestart-v0-baseline.apk` | `fe52e248664bf6a97d7599b507a448600f4e0190422228a84efde6d4125e85fa` |
| `v1` – med kompatibilitetsrettelser | `qa/artifacts/Safestart-v1-fixed.apk` | `12ad333745337542db9eb3ad54cb23bd06ee2c5d30ae9a9b9e09316cdc5f2940` |
| `v2` – v1 + rettet opplåsing (N1), ikke kjørt i matrisen | `qa/artifacts/Safestart-v2-unlockfix.apk` | `b34b2f43eb10bc525a5395042bb1ccf3ed84313a8e42bc34faed50b187198df7` |

Begge er signert med samme nøkkel (`app/.signing/safestart.jks`), slik at
`adb install -r` beholder Device Owner mellom kjøringene.

**Hovedfunn:** fra Android 11 (API 30) er `v0` i praksis ødelagt som kiosk.
Barnet ser bare Sjakk og Meldinger; Ring, Kamera, Kart og Skyss vises som
«Ikke her» og kan ikke åpnes, fordi pakkesynlighet (package visibility) skjuler
de eksterne appene for `PackageManager.resolveActivity()`, som er den appen
bruker til å bygge lock-task-allowlisten. `v1` retter dette med `<queries>`.
I tillegg er strømmenyen (med «Emergency») tilgjengelig inne i lock task på
Android 9–11 i `v0`, og `v1` fjerner den med `setLockTaskFeatures(NONE)`.

**Ett alvorlig funn står åpent i begge bygg:** «Lås opp telefonen» låser ikke
opp på Android 9–15, altså alle versjoner fra API 28 og oppover (se N1), mens
den virker på Android 7–8. `v2` retter dette, men er ikke kjørt i matrisen ennå
— se 5.1.

Alle ni versjoner er nå kjørt, begge bygg (18 kjøringer). Fra Android 12 til 15
er mønsteret identisk med Android 11: `v0` skjuler Ring, Kamera, Kart og Skyss
bak «Ikke her», `v1` gjør dem synlige og åpner dem. Kamera-flisen virker i alle
versjoner, men selve AOSP-kameraappen krasjer i emulatoren (miljøbegrensning).

## 2. Metode

- Emulator: `emulator 37.3.10.0`, headless, `-no-window -no-snapshot`, GPU
  `swiftshader_indirect`, 720x1280 @ 320 dpi, 2 GiB RAM.
- Systembilder: AOSP `default/arm64-v8a` fra `dl.google.com`, ett om gangen.
  Bildet for forrige versjon slettes før neste hentes (disken på maskinen er
  nesten full, jf. oppdraget).
- AVD-er lages for hånd (`qa/harness/make-avd.sh`), fordi SDK-et mangler
  `cmdline-tools`/`avdmanager`.
- Datapartisjon: `disk.dataPartition.size=2G` (suffiksform — bytes-form blir
  overstyrt til 6 GiB og emulatoren krasjer på full disk), seedet fra et ekte
  550 MB ext4-bilde (`qa/harness/large-userdata.sh`). Uten dette blir `/data`
  1 MB på API 28+, og zygote henger før `sys.boot_completed`.
- Roller: appen settes som **Device Owner** (`dpm set-device-owner`), som er
  forutsetningen for ekte kioskmodus.
- Testapplikasjoner: AOSP-bildene mangler telefon, SMS og Skyss. Derfor
  installeres stand-ins bare når bildet mangler handler:
  `qa/artifacts/qadialer.apk` (`no.safestart.qadialer`, håndterer `tel:`/
  `sms:`/APP_MESSAGING) og `qa/artifacts/qaskyss.apk` (`no.skyss.billett`,
  første kandidat i `Catalog.skyssPackage()`).
- Hver kjøring (`qa/harness/suite.py`) gjør: installér → sett Device Owner →
  les flisene → åpne Ring/Meldinger/Kamera/Skyss → rømme­forsøk (HOME,
  oversikt, statuslinje-sveip, BACK, `am start` av en fremmed app) → Sjakk og
  tilbake → skjult foreldredør (langt trykk + PIN) → direkte `am start` av
  `ParentActivity` uten PIN → les/skriv foreldrenummer → «Mamma & Pappa» →
  lås opp / lås igjen → strømmeny (API 28+) → omstart.
- Bevis per steg: skjermbilder (`NN-*.png`), `uiautomator`-dumper
  (`ui-*.xml`, `texts-*.txt`), `dumpsys`-utdrag (`state-*.txt`), logcat
  (`logcat-*.txt`) og `summary.json` i `qa/results/api<API>-<bygg>/`.

## 4. Funn med bevis

### F1 — KRITISK: pakkesynlighet ødelegger kiosken fra Android 11 (API 30+)

`Catalog.resolvePackage()` bruker `PackageManager.resolveActivity()`
(`app/src/no/safestart/kiosk/Catalog.java:81`). Fra API 30 returnerer dette
`null` for alle pakker appen ikke har erklært synlighet for. Da blir
`Kiosk.allowlist()` (`Kiosk.java:53-66`) bare appens egen pakke,
`setLockTaskPackages()` (`Kiosk.java:77`) låser barnet inne med en allowlist på
én pakke, og hver eksterne flis blir «Ikke her».

Empirisk bekreftet på Android 11 med `v0`
(`qa/results/api30-baseline/summary.json`):

```
tiles home: phone=Ikke her, sms=SMS til kjente, camera=Ikke her,
            maps=Ikke her, skyss=Ikke her, chess=Mot en bot
launch_phone  = BLOCKED (still no.safestart.kiosk/.HomeActivity)
launch_camera = BLOCKED
launch_skyss  = BLOCKED
```

På Android 7–10 er de samme flisene «Alltid tilgjengelig»/«Ta bilder»/
«Bussbillett» og åpner riktig app — så dette er en ren versjonsregresjon.

**Retting (v1):** `<queries>`-blokk i `app/AndroidManifest.xml` med
DIAL/`tel:`, MAIN+APP_MESSAGING, VIEW/`sms:`, STILL_IMAGE_CAMERA, VIEW/`geo:`
og eksplisitte `<package>` for `no.skyss.billett`, `no.skyss.reise`, `no.skyss`,
`no.skyss.tickets`. `<queries>` ignoreres på API 23–29, så den er trygg der.

**Verifisert på Android 11 med v1**
(`qa/results/api30-fixed/summary.json`):

```
tiles home: phone=Alltid tilgjengelig, sms=SMS til kjente,
            camera=Ta bilder, maps=Ikke her, skyss=Ikke her, chess=Mot en bot
allowlist (4): [no.safestart.kiosk, com.android.dialer,
                com.android.messaging, com.android.camera2]
launch_phone = opened com.android.dialer/.main.impl.MainActivity
launch_sms   = opened com.android.messaging/.ui.conversationlist.ConversationListActivity
```
Altså: Ring, Meldinger og Kamera er tilbake i allowlisten og kan åpnes, der
`v0` blokkerte dem. Skyss-flisen kunne ikke verifiseres i akkurat denne
kjøringen, fordi testapplikasjonen `qaskyss.apk` feilet med installasjonsfeil på
enheten (`failed to install: copy_to_file …`), så `no.skyss.billett` fantes
ikke og flisen viste korrekt «Ikke her».

Samme flis er derimot **verifisert på Android 12, 13, 14 og 15** med `v1`
(`qa/results/api31-fixed`, `api33-fixed`, `api34-fixed`, `api35-fixed`):

```
launch_skyss = opened no.skyss.billett/.MainActivity
```

Det bekrefter F1-rettelsen også for Skyss; bare API 30-kjøringen mangler den.

`Catalog.isInstalled()` fanget alle unntak og returnerte `false` uten spor
(`Catalog.java:133-140`). Nå fanges `PackageManager.NameNotFoundException`
eksplisitt, pakkenavnet logges, og `<package>`-oppføringene i `<queries>` gjør
den synlig på API 30+.

### F3 — HØY: strømmeny gir rømningsvei i lock task på Android 9–11

Fra API 28 er `LOCK_TASK_FEATURE_GLOBAL_ACTIONS` slått på som standard, så
strømmenyen (med «Emergency» = nødtelefon) er tilgjengelig selv om appen er i
lock task. Empirisk bevis (`power_menu_texts` i `summary.json`):

- API 28 `v0`: `['Power off', 'Restart', 'Screenshot']`
- API 29 `v0`: `['Power off', 'Restart', 'Screenshot', 'Emergency']`
- API 30 `v0`: `['Emergency', 'Power off', 'Restart']`
- API 28/29 `v1`: ingen meny — bare kioskskjermen ble avbildet

**Retting (v1):** `setLockTaskFeatures(admin, LOCK_TASK_FEATURE_NONE)` bak
`SDK_INT >= 28` i `Kiosk.lock()` (`Kiosk.java:69-110`), i samme `try` som
`setLockTaskPackages()` fordi Android 14 slår dem sammen til én policy, og
`getLockTaskPackages()` logges etterpå for verifisering.

### F4 — MIDDELS: `setStatusBarDisabled` har ingen effekt i lock task

Dokumentert av Android; returverdien ble ignorert. `v1` logger
`Log.w` når kallet returnerer `false`, og manifestet ber om
`MANAGE_DEVICE_POLICY_STATUS_BAR` for API 34+.

### F5 — MIDDELS: keyguard kan bli stående med PIN

`setKeyguardDisabled()` returnerer `false` når telefonen har PIN/mønster, og
telefonen stopper da på låseskjermen etter omstart. `v1` logger feilen og
kaller `setPasswordQuality(PASSWORD_QUALITY_UNSPECIFIED)` (API 24+).

### F6 — MIDDELS: ingen gjenoppretting etter omstart

Det fantes ingen `BOOT_COMPLETED`-mottaker. `v1` legger til
`app/src/no/safestart/kiosk/BootReceiver.java` som bare kaller
`Kiosk.lock(c, new Prefs(c))` — aldri `startActivity`, som ville være blokkert
for bakgrunnsstart fra API 29. `LOCKED_BOOT_COMPLETED` hoppes bevisst over
fordi `Prefs` ligger i credential-encrypted lagring.

### F7–F12 — øvrige kompatibilitetsrettelser i `v1`

| # | Rettelse | Hvor |
|---|---|---|
| F7 | egen splash på API 31+ | `app/res/values-v31/styles.xml` |
| F8 | `resizeableActivity="false"` (delt skjerm kan klippe rutenettet) | `AndroidManifest.xml`, tre aktiviteter |
| F9 | Force Dark av (papirpaletten ble ødelagt på 29+) | `app/res/values-v29/styles.xml` |
| F10 | `CALL_PHONE` gis av Device Owner via `setPermissionGrantState` | `Kiosk.java`, `ParentActivity.java:159-161` |
| F11 | `uses-feature android.hardware.telephony required="false"` | `AndroidManifest.xml` |
| F12 | tema samlet i `@style/Safestart` | `app/res/values/styles.xml` |

### N1 — HØY, ÅPENT: «Lås opp telefonen» låser ikke opp på Android 9–15

Bekreftet i **alle** kjøringer på Android 9–15, både `v0` og `v1` — det vil si
API 28, 29, 30, 31, 33, 34 og 35. Etter trykk på «Lås opp telefonen» står
`lock_task=True` fortsatt, og forgrunnen er tilbake på
`no.safestart.kiosk/.HomeActivity` i stedet for foreldreskjermen:

```
# fra hver summary.json (lock.unlocked / foreground.unlocked)
api28-baseline  tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api28-fixed     tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api29-baseline  tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api29-fixed     tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api30-baseline  tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api30-fixed     tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api31-fixed     tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api33-baseline  tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api33-fixed     tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api34-baseline  tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api34-fixed     tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api35-baseline  tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
api35-fixed     tap=True lock=True fg=no.safestart.kiosk/.HomeActivity
```

På API 24 og 26 virker samme knapp i begge bygg (`lock=False`, forgrunn
`ParentActivity`), så feilen er versjonsavhengig og slår inn fra Android 9.

Skjermbildene `16-unlocked.png` og `17-relocked.png` er byte-identiske, dvs.
kiosken var allerede tilbake da «opplåst»-tilstanden ble målt.

Sannsynlig årsak: `HomeActivity` er `launchMode="singleInstance"`, så
`ParentActivity` havner i en annen task. `stopLockTask()` avslutter bare lock
task for **egen** task, og siden `HomeActivity` er persistent HOME, gjenopptas
den og `Kiosk.enter()` låser på nytt i `onResume`.

**Retting i v2:** `Prefs.isUnlocked()`-flagg som `HomeActivity.onResume`
respekterer. v2 er bygget, men ikke kjørt i matrisen (se 5.1).
«Camera keeps stopping» i det headless emulatoren. Flisen gjør jobben sin
(tillatelsesdialog → kamera startes), men selve kameraopplevelsen kan ikke
godkjennes uten ekte telefon.

### N3 — MILJØ: Kart er utestbart i emulatoren

AOSP-bildene har ingen `geo:`-handler, så flisen viser «Ikke her» overalt.
Må testes på telefon med Google Maps installert.

### N4 — UX: «Ikke her» skjuler forskjellen mellom «ikke installert» og «ikke synlig»

På API 30+ med `v0` vises samme tekst for en pakke som finnes men er usynlig,
som for en pakke som mangler. Med `<queries>` på plass forsvinner årsaken, men
loggen bør skille de to tilfellene (deler av dette er gjort i F2).

## 5. Hva som gjenstår

### 5.1 Gjenstår: verifiser v2 (N1) i emulator

Selve matrisen er komplett: ni versjoner × to bygg = 18 kjøringer i
`qa/results/`. Det som gjenstår er å kjøre `v2` gjennom samme rigg, slik at
N1-rettelsen blir empirisk bevist og ikke bare kodegjennomgått.

Forsøket ble startet på API 35, men vertsmaskinen sluttet å gi emulatoren
maskinvareakselerasjon etter at minne og disk var presset:

```
$ .androidsdk/emulator/emulator -accel-check
accel:
138
accel

$ .androidsdk/emulator/emulator -avd api35 -no-window -no-audio -no-snapshot
ERROR | arm64-v8a emulation currently requires hardware acceleration!
CPU acceleration status:
```

`kern.hv_support` er 1 og ingen emulatorprosess står igjen, men
Hypervisor.framework svarer ikke for nye prosesser (16 GB RAM, ca. 110 MB frie
sider, komprimator ca. 2,8 GB, swap 1,4 av 3,0 GB). Samme AVD startet helt
fint tidligere på dagen, så dette er en tilstand på vertsmaskinen — ikke noe i
appen.

Kjør når maskinen har ledig minne og 6–8 GB ledig disk:

```bash
bash qa/harness/fix-label.sh 35 v2 qa/artifacts/Safestart-v2-unlockfix.apk
bash qa/harness/fix-label.sh 28 v2 qa/artifacts/Safestart-v2-unlockfix.apk
```

Bedre enn emulator: installer `v2` på en ekte telefon med Device Owner og trykk
«Lås opp telefonen». Det er den eneste måten å bekrefte N1 på ordentlig, siden
feilen handler om tasker og lock task, ikke om skjermbildet.

### 5.1.1 Erfaringer fra disk- og minnejakten (nyttige for gjentakelse)

Oppdraget ba om å slette forrige versjons miljø når plassen blir knapp. Det ble
gjort hver gang (`bash qa/harness/teardown.sh <API> --drop-image`), men macOS
og iCloud fylte disken igjen like fort som den ble tømt: ledig plass svingte
mellom 0,88 og 8,5 GB på en 228 GB disk. To mekanismer hjalp:

```bash
bash qa/harness/autosweep.sh 31 33 34 35   # venter på ledig plass, prøver på nytt
bash qa/harness/fix-label.sh 35 fixed <apk> # fyller inn én manglende kjøring
```
### 5.2 Kode: hva v2 endrer

`v2` er bygget (`qa/artifacts/Safestart-v2-unlockfix.apk`) og retter N1:

- `Prefs.isUnlocked()` / `setUnlocked()` – nytt flagg.
- `ParentActivity`: «Lås opp telefonen» setter flagget og lukker seg (den kan
  ikke avslutte lock task for HomeActivitys task).
- `HomeActivity.onResume()`: hvis flagget er satt kalles `Kiosk.unlock()`,
  ellers `Kiosk.enter()` som før.
- «Lås telefonen til Safestart» nullstiller flagget.

Bygget har samme signatur som `v0`/`v1`, så `adb install -r` oppå en eksisterende
installasjon beholder Device Owner. Se 5.1 for hvordan det verifiseres.

### 5.3 Øvrig
1. Test Kamera og Kart på en ekte telefon (N2, N3).
2. Vurder å droppe `Ui.immersive()` på API 24–27: systemveiledningen
   «Viewing full screen — To exit, swipe down from the top — GOT IT» lærer
   barnet en utvei som lock task ellers stenger. (Funnet under testing;
   testriggen måtte forhåndsbekrefte veiledningen for at trykkene skulle nå
   frem.)

### Miljømerknader fra kjøringen (nyttige for den som gjentar testen)

- `setsid` finnes ikke på macOS — bruk `nohup … &` for bakgrunnsjobber.
- Systembildet for API 28+ har en `userdata.img` på bare 1 MB som emulatoren
  ikke utvider; da henger zygote og `sys.boot_completed` kommer aldri. Bruk
  `qa/harness/large-userdata.sh` (550 MB ext4) som seed, og skriv
  `disk.dataPartition.size=2G` med suffiks (bytes-form blir overstyrt til
  6 GiB, som krasjer på full disk).
- Emulatoren tåler ikke at to instanser overlapper: `adb emu kill` + pause før
  neste boot, ellers kommer «Failed to setup emulator in a timely fashion».
- AOSP-bildene mangler telefon/SMS/Kart/Skyss; derfor
  `qa/helper-apps/` + `qa/artifacts/qadialer.apk` og `qaskyss.apk`.
